# Вклад в проект ToroidalDB

Спасибо за интерес к участию в развитии ToroidalDB! Мы рады любому вкладу от сообщества.

## Как внести вклад

### 1. Сообщить об ошибке

Если вы нашли ошибку, пожалуйста, создайте issue с:
- Четким описанием проблемы
- Шагами для воспроизведения
- Ожидаемым и фактическим поведением
- Версией ToroidalDB
- Информацией об окружении (OS, Rust версия и т.д.)

### 2. Предложить улучшение

Мы приветствуем предложения по улучшению функциональности:
- Создайте issue с описанием предлагаемой функции
- Объясните, почему это улучшение необходимо
- Опишите возможную реализацию

### 3. Исправить ошибку или добавить функцию

#### Подготовка окружения

1. Форкните репозиторий
2. Клонируйте форк:
   ```bash
   git clone https://github.com/nanocubit/toroidal-db.git
   cd toroidal-db
   ```
3. Установите Rust:
   ```bash
   curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
   rustup install stable
   rustup default stable
   ```
4. Установите зависимости:
   ```bash
   cargo build
   ```

#### Процесс разработки

1. Создайте новую ветку:
   ```bash
   git checkout -b feature/your-feature-name
   ```
2. Внесите изменения
3. Добавьте тесты для новых функций
4. Убедитесь, что все тесты проходят:
   ```bash
   cargo test
   ```
5. Отформатируйте код:
   ```bash
   cargo fmt
   ```
6. Проверьте с помощью clippy:
   ```bash
   cargo clippy -- -D warnings
   ```
7. Зафиксируйте изменения:
   ```bash
   git add .
   git commit -m "feat: add your feature description"
   ```
8. Запушьте ветку:
   ```bash
   git push origin feature/your-feature-name
   ```
9. Создайте Pull Request

### Стиль кодирования

#### Rust
- Следуйте рекомендациям `rustfmt`
- Используйте `clippy` для проверки качества кода
- Пишите документацию для публичных функций и структур
- Добавляйте тесты для новой функциональности

#### Именование
- Используйте `snake_case` для функций и переменных
- Используйте `PascalCase` для структур и перечислений
- Используйте `SCREAMING_SNAKE_CASE` для констант

#### Коммиты
Используйте семантические сообщения коммитов:
- `feat:` для новых функций
- `fix:` для исправлений ошибок
- `docs:` для изменений в документации
- `test:` для добавления или изменения тестов
- `refactor:` для рефакторинга
- `chore:` для прочих изменений

### Тестирование

Все изменения должны быть покрыты тестами:
- Добавляйте unit-тесты для новых функций
- Пишите интеграционные тесты для новых компонентов
- Убедитесь, что все существующие тесты проходят

Запуск тестов:
```bash
# Все тесты
cargo test

# Только unit-тесты
cargo test --lib

# Только интеграционные тесты
cargo test --test '*'

# Тесты с подробным выводом
cargo test -- --nocapture
```

### Документация

- Обновляйте документацию при добавлении новых функций
- Пишите понятные комментарии в коде
- Обновляйте README.md при значительных изменениях

## Архитектура проекта

```
src/
├── main.rs          # Точка входа
├── storage.rs       # Модуль хранения данных
├── math.rs          # Математические функции
├── metrics.rs       # Сбор метрик
├── admin_ui.rs      # Веб-интерфейс администратора
├── topology/        # Топологические операции
│   ├── mod.rs
│   ├── edges.rs
│   ├── algebra.rs
│   └── ricci_flow.rs
└── tql/             # TQL v2.0 модуль
    ├── mod.rs
    ├── ast.rs       # Абстрактное синтаксическое дерево
    ├── parser.rs    # Парсер запросов
    ├── executor.rs  # Исполнитель запросов
    ├── graph.rs     # Графовые операции
    ├── coordinator.rs # Координатор запросов
    └── transaction.rs # Транзакции
```

# Специфичные для тороидальной топологии конструкции в TQL v2.0

## Обзор

TQL v2.0 включает специфичные для тороидальной топологии конструкции, которые учитывают уникальные свойства тороидального пространства, где края пространства соединены (0.0 соединяется с 1.0 в любом измерении). Это позволяет эффективно работать с циклическими и периодическими данными.

## Основные конструкции

### CONNECTEDTO операция

Конструкция `CONNECTEDTO` позволяет находить узлы, которые связаны с указанными узлами через определенные типы связей:

```
CONNECTEDTO(target_label, "relationship_type", "property_filter")
```

#### Параметры:
- `target_label`: метка целевых узлов
- `"relationship_type"`: тип связи (в кавычках)
- `"property_filter"`: необязательный фильтр по свойствам (в кавычках)

#### Пример:
```
MATCH (doc:Document) 
CONNECTEDTO(doc, "TAGGED_WITH", "quantum") 
RETURN doc.id 
LIMIT 20
```

### WITHIN HOPS операция

Конструкция `WITHIN HOPS` ограничивает количество шагов в графовом обходе:

```
WITHIN min_hops TO max_hops HOPS
```

или сокращенно:

```
WITHIN hops HOPS
```

#### Параметры:
- `min_hops`: минимальное количество шагов (опционально)
- `max_hops`: максимальное количество шагов
- `TO`: ключевое слово для указания диапазона (опционально)

#### Примеры:
```
WITHIN 2 HOPS           -- в пределах 2 шагов
WITHIN 1 TO 3 HOPS     -- от 1 до 3 шагов
```

### Полный синтаксис топологических запросов

```
MATCH (source:Label) 
CONNECTEDTO(target_label, "relationship_type", "property_filter") 
WITHIN min_hops TO max_hops HOPS 
RETURN source.id, target.id 
LIMIT count
```

## Реализация bidirectional BFS алгоритма

### Алгоритм обхода

Для эффективного поиска в тороидальном пространстве реализован bidirectional BFS (двунаправленный поиск в ширину):

1. **Прямой обход**: начиная с стартовых узлов, ищем вперед до `max_hops`
2. **Обратный обход**: начиная с целевых узлов, ищем назад до `max_hops`
3. **Поиск пересечений**: находим узлы, которые встречаются в обоих обходах на расстоянии `[min_hops, max_hops]`

### Учет тороидальной топологии

Алгоритм учитывает тороидальную топологию следующим образом:

- **Циклические связи**: узлы на краях пространства (например, 0.01 и 0.99) рассматриваются как близкие
- **Обертывание координат**: при расчете расстояний учитывается возможность "обернуть" через край пространства
- **Топологические инварианты**: сохраняются при обходе графа

## Примеры запросов

### Простой топологический запрос
```
MATCH (doc:Document) 
CONNECTEDTO(doc, "TAGGED_WITH", "quantum") 
WITHIN 2 HOPS 
RETURN doc.id 
LIMIT 20
```

### Запрос с диапазоном шагов
```
MATCH (user:User) 
CONNECTEDTO(user, "FOLLOWS", "active") 
WITHIN 1 TO 3 HOPS 
RETURN user.id, user.name 
LIMIT 10
```

### Гибридный топологический запрос
```
MATCH (start:Entity) 
CONNECTEDTO(target:Entity, "RELATED_TO") 
WITHIN 2 HOPS 
WHERE TOROIDALDISTANCE(target.vector, 0.3) 
RETURN start.id, target.id, target.score 
ORDER BY target.score 
LIMIT 15
```

### Распределенный топологический запрос
```
DISTRIBUTED MATCH (node:Node) 
CONNECTEDTO(node, "SIMILAR_TO", "verified") 
WITHIN 3 HOPS 
RETURN node.id, node.similarity 
LIMIT 50
```

## Архитектура реализации

### GraphOperations модуль

Модуль `src/tql/graph.rs` содержит реализацию:

- `bidirectional_bfs()`: основная функция двунаправленного поиска
- `find_connected_nodes()`: функция поиска соединенных узлов
- `matches_property_filter()`: проверка фильтров по свойствам

### Алгоритм bidirectional_bfs

```rust
pub async fn bidirectional_bfs(
    store: &PersistentStore,
    start_nodes: &[u64],
    min_hops: u32,
    max_hops: u32,
    rel_type: &str,
) -> Result<Vec<u64>, String>
```

Алгоритм:
1. Инициализирует очереди для прямого и обратного обхода
2. Выполняет BFS в обоих направлениях
3. Ищет пересечения на расстоянии `[min_hops, max_hops]`
4. Возвращает узлы, удовлетворяющие условиям

### Учет тороидальной топологии

При обходе графа учитываются тороидальные свойства:
- Узлы с координатами близкими к краям (0.0 и 1.0) рассматриваются как соседние
- Расстояния вычисляются с учетом возможности "обернуть" через край
- Сохраняются топологические инварианты при перемещении по графу

## Тестирование на графах с циклами

### Тестирование циклических графов

Специальные тесты проверяют работу на графах с циклами:

- **Тесты с циклическими связями**: проверяют корректность обхода в замкнутых графах
- **Тесты с граничными узлами**: проверяют обработку узлов на краях тороидального пространства
- **Тесты с топологическими инвариантами**: проверяют сохранение свойств при обходе

### Пример теста с циклами

```rust
// Создаем циклический граф: 1 -> 2 -> 3 -> 4 -> 1
store.add_edge(1, 2, "NEXT", 1.0)?;
store.add_edge(2, 3, "NEXT", 1.0)?;
store.add_edge(3, 4, "NEXT", 1.0)?;
store.add_edge(4, 1, "NEXT", 1.0)?; // Замыкаем цикл

// Тестируем bidirectional BFS
let results = GraphOperations::bidirectional_bfs(&store, &[1], 1, 2, "NEXT").await?;
```

## Производительность

### Оптимизации

- **Кэширование результатов обхода**: предотвращает повторные вычисления
- **Ранняя остановка**: прекращает обход при достижении `max_hops`
- **Эффективное хранение посещенных узлов**: использует HashMap для быстрой проверки

### Сложность

- **Временная сложность**: O(b^d), где b - коэффициент ветвления, d - глубина поиска
- **Пространственная сложность**: O(b^d) для хранения очередей обхода

## Заключение

Специфичные для тороидальной топологии конструкции в TQL v2.0 позволяют эффективно работать с циклическими и периодическими данными, учитывая уникальные свойства тороидального пространства. Это открывает новые возможности для анализа данных, где важны топологические связи и циклические зависимости.

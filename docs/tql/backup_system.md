# Резервное копирование в ToroidalDB

## Обзор

ToroidalDB включает встроенную систему резервного копирования, которая позволяет создавать, хранить и восстанавливать резервные копии данных. Система поддерживает как локальные, так и распределенные резервные копии с возможностью автоматического планирования.

## Архитектура резервного копирования

### BackupManager

Центральный компонент системы резервного копирования:

- `create_backup()` - создание новой резервной копии
- `restore_from_backup()` - восстановление из резервной копии
- `list_backups()` - получение списка доступных резервных копий
- `cleanup_old_backups()` - удаление устаревших резервных копий
- `schedule_regular_backups()` - планирование регулярных резервных копий

### Формат резервной копии

Резервные копии создаются в формате TAR.GZ архива, содержащего:

- `nodes.json` - все узлы графа с векторами и свойствами
- `info.json` - метаданные резервной копии (время создания, размер, количество узлов)

### Consistent Hashing

Для распределенных резервных копий используется consistent hashing для равномерного распределения данных по шардам.

## Агрегации в резервных копиях

Резервные копии поддерживают сохранение агрегированных данных:

```sql
-- Создание резервной копии с агрегированными данными
MATCH (user:User)
RETURN 
  COUNT(user) AS total_users,
  AVG(user.score) AS avg_score,
  MIN(user.created_at) AS earliest_user,
  MAX(user.last_seen) AS latest_activity
```

## Транзакции и резервные копии

Система обеспечивает согласованность данных при создании резервных копий во время транзакций:

```sql
BEGIN TRANSACTION
CREATE (user:User {name: "Alice", email: "alice@example.com"})
MATCH (group:Group {id: 1})
CREATE (user)-[:MEMBER_OF]->(group)
-- Резервная копия будет создана с учетом всех изменений в транзакции
COMMIT
```

## Распределенное резервное копирование

В распределенной системе резервные копии создаются на каждом шарде независимо, а затем объединяются на уровне координатора.

### Scatter/Gather для резервных копий

1. **Scatter**: запрос на создание резервной копии отправляется на все шарды
2. **Local Processing**: каждый шард создает свою часть резервной копии
3. **Gather**: результаты собираются и объединяются в глобальную резервную копию

## Планирование резервных копий

Система поддерживает автоматическое планирование регулярных резервных копий:

- Ежедневные резервные копии
- Еженедельные резервные копии
- Ежемесячные резервные копии
- Настройка времени и частоты

### Пример планирования

```rust
// Создание резервной копии каждые 6 часов
backup_manager.schedule_regular_backups(store, 6).await;
```

## Управление сроком хранения

Система автоматически удаляет устаревшие резервные копии:

- Настройка периода хранения (по умолчанию 7 дней)
- Автоматическая очистка при создании новых резервных копий
- Поддержка политики хранения (например, 7 daily, 4 weekly, 12 monthly)

## Безопасность

### Авторизация операций

- `backup:create` - разрешение на создание резервных копий
- `backup:restore` - разрешение на восстановление из резервных копий
- `backup:list` - разрешение на просмотр списка резервных копий
- `backup:schedule` - разрешение на планирование резервных копий

### Шифрование резервных копий

В будущих версиях планируется поддержка шифрования резервных копий с использованием AES-256.

## Производительность

### Оптимизации

- **Параллельное создание** - использование rayon для параллельной обработки
- **Инкрементальные резервные копии** - копирование только измененных данных
- **Сжатие данных** - использование gzip для уменьшения размера
- **Кэширование** - предотвращение повторного создания одинаковых резервных копий

### Метрики производительности

- Время создания резервной копии
- Размер резервной копии
- Время восстановления
- Использование ресурсов во время резервного копирования

## Восстановление после сбоев

### Процесс восстановления

1. Определение последней целостной резервной копии
2. Загрузка данных из архива
3. Валидация целостности данных
4. Восстановление индексов и связей
5. Проверка консистентности топологии

### Точки восстановления

Система поддерживает создание точек восстановления (recovery points) с возможностью отката к определенному моменту времени.

## Примеры использования

### Создание ежедневной резервной копии

```bash

  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{"interval_hours": 24}'
```

### Восстановление из последней резервной копии

```bash

curl -k -X GET https://localhost:8443/backup/list \
  -H "Authorization: Bearer <token>"

# Затем восстанавливаем из конкретной резервной копии
curl -k -X POST https://localhost:8443/backup/restore \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{"backup_id": "backup_1234567890"}'
```

### Создание резервной копии с описанием

```bash
curl -k -X POST https://localhost:8443/backup/create \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{"description": "Pre-migration backup"}'
```

## Интеграция с TQL

Резервное копирование интегрировано с TQL v2.0:

```sql
-- Создание резервной копии с фильтрацией
BACKUP MATCH (user:ActiveUser) 
WHERE user.last_seen > "2024-01-01" 
AS "recent_users_backup"

-- Восстановление из резервной копии
RESTORE FROM "recent_users_backup" 
MATCH (user:User) 
RETURN COUNT(user) AS restored_count
```

## Заключение

Система резервного копирования в ToroidalDB обеспечивает:

- **Надежность**: согласованные резервные копии с поддержкой транзакций
- **Масштабируемость**: поддержка распределенных резервных копий
- **Автоматизацию**: планирование регулярных резервных копий
- **Безопасность**: авторизация и потенциальное шифрование
- **Производительность**: оптимизированные алгоритмы создания и восстановления
- **Интеграцию**: поддержка с TQL и другими компонентами системы

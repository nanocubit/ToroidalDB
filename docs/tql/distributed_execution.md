# Распределённое выполнение в TQL v2.0

## Обзор

TQL v2.0 поддерживает распределённое выполнение запросов, позволяя масштабировать систему на несколько узлов и обрабатывать большие объёмы данных. Распределённое выполнение реализовано через систему шардирования с использованием consistent hashing и координатора запросов.

## Архитектура распределённого выполнения

### QueryCoordinator

Координатор запросов отвечает за:
- **Маршрутизацию запросов**: определение, какие шарды должны обработать запрос
- **Consistent hashing**: равномерное распределение данных по шардам
- **Управление шардами**: отслеживание доступных шардов и их состояния

#### Основные функции:
- `route_query()`: определение шардов для обработки запроса
- `route_node()`: определение шарда для конкретного узла
- `initialize_hash_ring()`: инициализация consistent hashing кольца

### DistributedExecutor

Исполнитель распределённых запросов:
- **Scatter**: распределение запроса по нескольким шардам
- **Gather**: сбор и объединение результатов из разных шардов
- **Merge**: объединение результатов с соблюдением лимитов и сортировки

#### Основные функции:
- `execute_distributed()`: выполнение распределённого запроса
- `merge_top_k()`: объединение топ-K результатов из разных шардов

## Механизм шардирования

### Consistent Hashing

Для равномерного распределения данных по шардам используется consistent hashing:

1. **Virtual Nodes**: каждый физический шард представлен несколькими виртуальными узлами на хэш-кольце
2. **Uniform Distribution**: обеспечивает равномерное распределение данных
3. **Scalability**: позволяет легко добавлять и удалять шарды

### Алгоритм маршрутизации

```
Node ID -> Hash Function -> Hash Ring -> Shard ID
```

## Scatter/Gather механизм

### Scatter Phase

1. **Query Routing**: координатор определяет, какие шарды должны обработать запрос
2. **Parallel Execution**: запрос отправляется на несколько шардов параллельно
3. **Local Processing**: каждый шард обрабатывает только свою часть данных

### Gather Phase

1. **Result Collection**: сбор результатов из всех участвующих шардов
2. **Global Sorting**: объединение и сортировка результатов по глобальным критериям
3. **Limit Enforcement**: применение глобального лимита к объединённым результатам

## Примеры распределённых запросов

### Простой распределённый запрос
```
DISTRIBUTED MATCH (node:Label) 
WHERE TOROIDALDISTANCE(node.vector, 0.4) 
RETURN node.id, node.score 
LIMIT 5
```

### Гибридный распределённый запрос
```
DISTRIBUTED MATCH (user:User)-[:FOLLOWS]->(friend:User) 
WHERE TOROIDALDISTANCE(friend.vector, 0.3) 
RETURN user.id, friend.id, friend.score 
LIMIT 10
```

### Топологический распределённый запрос
```
DISTRIBUTED MATCH (doc:Document) 
CONNECTEDTO(doc, "TAGGED_WITH", "quantum") 
WITHIN 2 HOPS 
RETURN doc.id, doc.similarity 
LIMIT 20
```

## Конфигурация распределённого выполнения

### Настройка шардирования

```rust
let shards = vec![shard1, shard2, shard3];
let coordinator = QueryCoordinator::new(3, shards);
```

### Использование распределённого исполнителя

```rust
let executor = DistributedExecutor::new(coordinator);
let results = executor.execute_distributed(query).await?;
```

## Оптимизации распределённого выполнения

### 1. Parallel Scatter
- Запросы отправляются на шарды параллельно
- Используется async/await для эффективного управления потоками

### 2. Early Termination
- Ранняя остановка обработки на шардах при достижении лимита
- Оптимизация использования ресурсов

### 3. Result Caching
- Кэширование результатов распределённых запросов
- Ускорение повторных запросов

## Обработка ошибок

### Fault Tolerance
- Обработка сбоев отдельных шардов
- Продолжение выполнения при частичных сбоях
- Логирование ошибок для диагностики

### Retry Logic
- Повторные попытки при временных сбоях
- Экспоненциальное увеличение задержки между попытками

## Производительность

### Масштабируемость
- Линейное ускорение с увеличением числа шардов
- Эффективное использование ресурсов нескольких узлов

### Latency Optimization
- Минимизация сетевых задержек
- Оптимизация объёма передаваемых данных

## Тестирование распределённого выполнения

### Локальные тесты
- Использование нескольких локальных шардов для тестирования
- Проверка корректности маршрутизации
- Тестирование scatter/gather механизма

### Интеграционные тесты
- Тестирование с реальными наборами данных
- Проверка производительности
- Сравнение с локальным выполнением

## Заключение

Распределённое выполнение в TQL v2.0 обеспечивает:
- **Масштабируемость**: возможность обработки больших объёмов данных
- **Производительность**: параллельная обработка на нескольких узлах
- **Надёжность**: устойчивость к частичным сбоям
- **Гибкость**: поддержка всех типов запросов (векторных, графовых, гибридных)
